# 開発の進め方(AI・Colab・作業の保存)
{: .no_toc }

開発環境は前の2回と同じ Colab です。ただし IoT 設計制作実験は **3回にまたがる**ので、
Colab に作業を残しておけないことと、AI の無料枠に週ごとの上限があることに気をつけます。

1. TOC
{:toc}

## 毎回の始め方

1. **IoT 設計制作実験用のノートブック**を開いて、上から順に実行する。

   [![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/hasevr/ICTEx5/blob/main/notebooks/iot.ipynb)

2. 2回目以降は「**前回の作業を戻す**」のセルで、前回ダウンロードした ZIP をアップロードする。
   1回目は「新しいプロジェクトを作る」のセルで、サンプルをコピーして始める。
3. 「▶ ESP32 ブリッジを開く」を Chrome / Edge の新しいタブで開き、ESP32 をつないで「ESP32 に接続」。
4. 左下の「ターミナル」で `cd /content/work && agy`。最初の依頼には「**AGENTS.md と PROJECT.md を読んでから**」と添える。

## 毎回の終わり方(必ず)

**「作業を ZIP でダウンロード」のセルを実行**して、自分たちのファイルを PC に保存してください。
Colab の VM は、しばらく操作しないと切れ、時間がたつとリセットされ、**中身はすべて消えます**。
大学のアカウントでは Google Drive に保存できないので、この ZIP が唯一の保存先です。

- ZIP には、`/content/work` の中の自分たちのファイル(ソース、`sdkconfig`、`PROJECT.md` など)が入ります。ビルドの結果は入りません(次回ビルドし直します)。
- 作業の途中でも、区切りのよいところでダウンロードしておくと安心です。
- Raspberry Pi の上のファイルは SD カードに残ります。ただし SD カードを書き直すと消えるので、大事なものは `scp` で PC にコピーしておきます
  (`scp pi@10.0.1.23:app.py .`)。

## グループでの分担とファイルの受け渡し

- **担当をはっきり分ける**: 例えば「センサノードの ESP32(A さん)」「アクチュエータ側の ESP32(B さん)」「Raspberry Pi のサーバと画面(C さん)」。
  ESP32 のプログラムは各自の Colab で、それぞれのキットで作ります。
- **つなぎ目(通信の仕様)を先に決める**: どの機器が、どの宛先に、どんな形式(URL のパラメータ、JSON など)で、どのくらいの頻度で送るか。
  決めた仕様は `PROJECT.md` に書き、メンバー全員の `PROJECT.md` に同じものを入れておきます。AI はこれを読んで、仕様どおりに作ります。
- **ファイルの受け渡し**は、ZIP や個々のファイルを、学生用の Scrapbox・Slack・LMS などで渡します。
  GitHub を使えるメンバーがいれば、グループのリポジトリを作ってもかまいません(Colab のターミナルで `git` が使えます)。
- **Raspberry Pi は 1 グループ 1 台**でサーバにするのが簡単です。ESP32 の宛先は、その Raspberry Pi の IP アドレス(画面に出るもの)です。

## AI の使い方と無料枠

- Antigravity CLI の無料枠は**1 人ごと、1 週間ごと**です。触覚提示実験では、授業 1 回ぶんの作業を全部 AI に任せると、Gemini の週の枠の約 3 割を使いました。
  **全員がそれぞれの AI を使えるよう**、担当を分けて並行して進めるのが効率的です。
- 依頼は小さく具体的に。「`PROJECT.md` の仕様の 2 番(ESP32 → Raspberry Pi の送信)だけを実装して」のように、仕様の番号で頼むとぶれません。
- AI は Raspberry Pi・実験室のネットワーク・センサの実物に触れません。実機で起きていることは人が見て、数値や症状で伝えます。
- **AI の変更は必ず読む**。発表会の質疑では「このコードは何をしているか」を説明できる必要があります。
- 主な依頼と結果は、ノートブックの「AI 利用の記録」に書いておきます(個人レポートで使います)。

## 使える構成

| やりたいこと | 使うもの | 出発点 |
|---|---|---|
| センサの値を集めて見せる | ESP32 → HTTP → Raspberry Pi のサーバ → ブラウザ | [HttpHaptic と `server/app.py`](../coop/) |
| サーバから機器を動かす | Raspberry Pi の応答で ESP32 に指示(周波数の例) | 同上 |
| 加速度・傾き・回転 | 9 軸センサ MPU-9250(SPI) | [キットの部品とセンサ](parts.html) の `Mpu9250` |
| 音を出す・振動を細かく制御する | D 級アンプ MAX98357A(I2S) | [D 級アンプで駆動する](../haptics/i2s.html) の `I2SHaptic` |
| ESP32 どうしで直接やりとり | ESP-NOW、Bluetooth LE | AI に「ESP-IDF v5.5 の ESP-NOW の例をもとに」と頼む |
| 近づいた・離れたを知る | Wi-Fi・BLE の電波強度(RSSI) | ESP-IDF の `wifi/scan` の例 |

Raspberry Pi には Python 3、Flask、git が入っています(新しいライブラリを pip で入れることは前提にしないでください。
Raspberry Pi がインターネットに出られないことがあります)。

{: .note }
Raspberry Pi を有線LAN でなく無線LAN につなぎたいときは、Raspberry Pi で
`sudo nmcli dev wifi connect ICT_EX5_2G password embedded` とします。無線LAN の同時接続数には限りがあるので、ESP32 を優先し、
必要なときだけにしてください。

## 外部のサービス

インターネット上のサービス(天気の API、通知のサービス、クラウドのデータベースなど)を使う構想もあり得ます。
実験室のネットワークから届くか、アカウントや料金が必要かを、早めに確かめてください。
個人情報やパスワードをプログラムに書いて共有しないこと。迷ったら教員・TA に相談してください。
