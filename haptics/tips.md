## ナイキスト周波数に気をつける

`main.c` では、標準では `hapticFunc()` が 1 ms に1回呼び出されます。つまりサンプリング周波数 1 kHz で波形を出力しています。
ナイキスト周波数(500 Hz)に近づくと、サンプリングの影響で波形が乱れます。
このため、僅かな周波数の変化が大きな波形の変化になり、**周波数の違いではなく波形の違いを知覚する**ことがあります。
下のアニメーションのように、f < fs/4 = 250 Hz まで、波形がきれいなのは f < fs/8 = 125 Hz くらいまでです。

![エイリアシング](https://upload.wikimedia.org/wikipedia/commons/thumb/c/cf/Aliasing_sinusoidal.gif/640px-Aliasing_sinusoidal.gif)

{: .note }
Colab のノートブックで、1 kHz でサンプリングした cos 波をグラフにしてみると(Gemini に頼めば数行です)、
どの周波数から形が崩れるか、書き込む前に目で確かめられます。

## 固有振動の共振周波数に気をつける

物は剛体ではなく変形します。バネ・ダンパー・質量の組み合わせで近似すると、一度変形させて離すとしばらく振動します。
これが固有振動で、その周波数が共振周波数です。

モータで外から振動を加えると、共振周波数の近くでは振幅が極端に大きくなります。
共振周波数から離れた周波数で実験しないと、**周波数ではなく振幅の変化から違いを知覚**してしまいます。
参考: [Resonance(Wikipedia)](https://en.wikipedia.org/wiki/Resonance)

## 高い周波数を使うには: USE_TIMER の有効化

`main.c` の先頭付近に

```c
//#define USE_TIMER   //  Whether use the timer or not. ...
```

という行があります。行頭のコメントを外すと `USE_TIMER` が定義され、`hapticFunc()` がタイマー割り込みで
より短い周期(標準 10 kHz)で呼ばれるようになり、高い周波数まで出力できます。
`#ifdef USE_TIMER` 〜 `#else` 〜 `#endif` で切り替わる箇所がいくつかあるので確認してください。

- タイマーの中で `printf()` などの重い処理を多く行うと、処理が間に合わなくなり動作しなくなります。
- タイマーの周期は 10 kHz が限界、出力する周波数としては 2 kHz が限界と考えてください。
- 人の触覚の感度は 250 Hz 付近が最も高く(閾値が最も低く)、1 kHz を越えるとかなり落ちるので、1 kHz 以下で実験するのが良いでしょう。
- 10 kHz の正弦波を出したければ 40 kHz 以上の周期が必要で、この方法ではできません
  ([esp_timer の ISR ディスパッチ](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32/api-reference/system/esp_timer.html) を使うとできるかもしれません)。

## キーボード入力で処理を切り替える

`main.c` の最後の方に、シリアル入力を受け取り、その文字に応じて処理を切り替える雛形があります
(`uart_read_bytes(UART_NUM_0, …)`)。ここを書き換えると、プログラムを書き換えずに、
上昇系列と下降系列を切り替えたり、周波数の変化量を調節したりできます。
`hapticFunc()` に伝えるには、グローバル変数を介するなどの工夫が必要です。

入力は、Colab のターミナルから `esp send "f 200"`、またはブリッジのタブの入力欄から送れます。

## デバッガ(JTAG)

キットの緑色の基板(FT232H)を使うと、ブレークポイントで止めて変数を見るなどのデバッグができます。
これは PC にローカルの開発環境(VS Code + ESP-IDF 拡張)を作った場合のみ使えます
([開発環境の準備](../setup.html) の付録)。
デバッガは実行を止めるので、波形を振動や音として感じたいときはブレークポイントを入れずに実行してください。
